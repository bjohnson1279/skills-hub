# Bot PR Effectiveness Evaluator

## Overview
This skill provides automated evaluation, scoring, and benchmarking for Pull Requests generated by automated developer bots (Jules, Bolt, Palette, Sentinel, Dependabot). It systematically assesses whether proposed code changes provide real algorithmic gains ($\mathcal{O}(N \times M) \to \mathcal{O}(N) + \mathcal{O}(M)$), memory optimization, security hardening, or accessibility enhancements without introducing regressions or domain drift.

## Dependencies
* `gh` (GitHub CLI authenticated with repository access)
* `python` 3.8+ or `uv`
* Reference skills: `bot-pr-triage-runner`, `pr-merge-conflict-resolver`

## Quick Start

Evaluate one or more PRs and produce a structured evaluation report:

```bash
# 1. Evaluate PRs across an entire multi-submodule workspace into structured JSON
python C:/Users/johns/.gemini/config/skills/bot-pr-effectiveness-evaluator/scripts/evaluate_pr.py evaluate \
  --workspace C:/Users/johns/DEV/inventory \
  --output evaluation.json

# Or evaluate an explicit list of PRs
python C:/Users/johns/.gemini/config/skills/bot-pr-effectiveness-evaluator/scripts/evaluate_pr.py evaluate \
  --pr-list "bjohnson1279/ams-proto#2,bjohnson1279/ams-proto#5" \
  --output evaluation.json \
  --base-dir C:/Users/johns/DEV/ams-proto

# 2. Render Markdown summary matrix
python C:/Users/johns/.gemini/config/skills/bot-pr-effectiveness-evaluator/scripts/evaluate_pr.py matrix \
  --input-file evaluation.json \
  --output evaluation_matrix.md
```

## Evaluation Framework

The evaluator scores PRs on a 0–100 scale across 4 core technical pillars:

1. **Algorithmic Complexity Reduction (+25 pts)**:
   - Replacement of $\mathcal{O}(N)$ linear searches inside loops with $\mathcal{O}(1)$ `Map`/hash lookups.
   - Replacement of concurrent individual $\mathcal{O}(N)$ database query loops (`Promise.all` calling single lookups) with a single batched repository query (`WHERE id IN (...)` / `getByIds`).
   - Pre-computation and caching of normalized tokens in class constructors to eliminate nested loop overhead.
   - Conversion of heavy iterator loops to indexed loops where appropriate.

2. **Memory & Garbage Collection Overhead (+15 pts)**:
   - Consolidation of chained array operations (`.map().filter()`, `.flatMap()`) into single-pass loops to eliminate intermediate allocations.
   - Hoisting repeated string lowercasing, regex compiling, and object spreading out of inner iteration loops.
   - Reduction of intermediate allocations during batch migrations and dry-run evaluations.

3. **Security & Data Invariant Preservation (+30 pts)**:
   - Proper HTML entity escaping / XSS protection on dynamic render templates.
   - Parameterized SQL query placeholders (`$1`, `?`) vs raw concatenation.
   - Row-Level Security (RLS) tenant claim propagation.
   - **Path Normalization Test Guard**: When evaluating security PRs addressing path traversal, verify that aggressive path normalization (e.g., `os.path.abspath`) used for boundary checks does not leak into downstream subprocess calls or break existing unit test mock assertions that expect relative path strings.

4. **Accessibility & Usability (+15 pts)**:
   - Centralized persistent screen reader live regions (`#sr-announcer` with `.sr-only` and `aria-live="polite"`) replacing dynamic `innerHTML` live region mutations.
   - Proper ARIA labels (`aria-label`, `aria-expanded`), modal focus trapping, and keyboard navigation.
   - WCAG 2.1 focus management: preserving `document.activeElement`, shifting focus to modal triggers/close buttons, and restoring focus upon modal dismissal.

5. **Risk, Defect & Hygiene Penalties**:
   - **Phantom Features / False Diffs (-35 pts)**: PR title/body claims to add or scaffold a feature (e.g. `feat(ux): Add empty states to table`), but the diff contains zero substantive code additions, or only deletes code and leaves behind scratch files.
   - **Uncleaned Scratch Verification Files (-25 pts)**: PR commits temporary test harnesses or scripts (`test_*.ts`, `test*.cjs`, `fix_*.php`, `update_*.php`).
   - **Unresolved Conflict Markers (-40 pts)**: Diff introduces or preserves lingering Git conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`).
   - **In-Memory Merge Conflicts (-20 pts)**: Sibling PRs that conflict against base commit state during `git merge-tree` simulation.
   - **Destructive Deletions (-40 pts)**: Massive deletions (>30 lines) in schema DDLs or entrypoints without replacements.

### Scoring Tiers
* **75–100**: *High Value (Merge Recommended)* — Confirmed algorithmic or security improvements with zero regressions.
* **50–74**: *Moderate Value (Safe to Merge)* — Clean, non-breaking cosmetic or accessibility improvements.
* **1–49**: *Low Value / Defective / Review Needed* — Marginal improvements, unfulfilled claims, or scratch files requiring manual inspection/remediation.
* **0**: *Zero-Diff / Destructive / Superseded (Close Recommended)* — Hallucinatory or harmful changes.

## Utility Scripts

### Subcommands in `evaluate_pr.py`

#### `evaluate`
Inspects PR metadata, files, and diff patterns:
```bash
python scripts/evaluate_pr.py evaluate \
  --pr-list "OWNER/REPO#NUM,OWNER/REPO#NUM" \
  --output <output.json> \
  [--base-dir <local_repo_path>]
```

#### `matrix`
Transforms JSON evaluation results into a GitHub-compatible Markdown summary table:
```bash
python scripts/evaluate_pr.py matrix \
  --input-file <evaluation.json> \
  --output <report.md>
```

## Common Mistakes
1. **Evaluating solely by CI status**: Automated bots can create zero-diff PRs that pass CI simply because they touch nothing; always check algorithmic and domain diffs.
2. **Ignoring Constructor Hoisting**: Normalizing strings inside `evaluate()` seems harmless until running batches of 50,000 records; constructor pre-normalization is essential for high-throughput DDD services.
